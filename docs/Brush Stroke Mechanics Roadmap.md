# Brush Stroke Mechanics Roadmap

This document is now the **primary implementation roadmap for stroke realism** in Graffux.

The existing `Material-Aware Paint Engine Roadmap.md` remains valid supporting research, but material behavior is **secondary**. The critical path here is limited to behavior that changes because of the brush and the way the hand moves it.

## Scope boundary

### In scope — brushstroke-specific mechanics

- pressure-driven contact and splay;
- stylus tilt and orientation changing the footprint;
- brush-tip aspect ratio and contact angle;
- directional bending from stroke motion;
- lag between hand direction and bristle/contact direction;
- hysteresis / memory in the contact shape;
- snap-back and recovery after directional changes;
- touchdown, dwell, stab, drag, flick and lift-off behavior;
- flat / round / filbert / rigger / fan-like morphology;
- coarse bristle bundles / sub-tufts;
- bristle cohesion and splitting as a **geometric brush-tip behavior**;
- structured rake/comb striation generated by brush geometry;
- deterministic replay of all mechanical state;
- live/commit/GPU parity for the resulting dab geometry;
- bounded mobile cost.

### Explicitly not on the primary path

These may interact with brush mechanics later, but they are not brushstroke mechanics and must not drive the current implementation sequence:

- pigment/color mixing;
- wet-paint transfer and reservoir chemistry;
- fluidity, viscosity and flow simulation;
- canvas/substrate surface texture or absorbency;
- wetness transport;
- diffusion/bleeding;
- impasto/material height evolution;
- optical wet/dry shading;
- spectral/Kubelka-Munk work.

Brush-tip texture that emerges from **bristle/tuft geometry** is in scope. Canvas surface texture is not.

---

## Current mechanical baseline

Graffux already has substantial stroke mechanics infrastructure:

- canonical `BrushSample` input with pressure, tilt, orientation, speed, distance, drawing angle and touch-major;
- deterministic `BrushSensorEngine` routes;
- dynamic size, opacity, flow, spacing, scatter, rotation, hardness and tip-ratio resolution;
- start/end taper;
- speed-sensitive thinning;
- first-touch blot, dwell growth and sharpness response;
- elongated tips and per-dab angle;
- follow-stroke rotation;
- count/scatter;
- incremental live dab generation;
- matching commit/replay generation;
- CPU and Vulkan renderers that already consume resolved dab radius/aspect/angle.

The important architectural opportunity is that renderers already understand the three basic contact-geometry outputs we need first:

```text
radius / width
aspect ratio
angle
```

So the next step does not require a new renderer. It requires a better brush-contact model.

---

## Mechanical architecture

```text
BrushSample
    ↓
Brush Sensor Resolution
    ↓
Brush Mechanical State
    ↓
Brush Contact State
    ↓
Resolved Dab / Tuft Geometry
    ↓
Existing CPU / Vulkan Renderer
```

### Brush Mechanical State

Persistent within one stroke where needed:

- bend direction;
- bend magnitude;
- angular lag;
- splay amount;
- recovery/snap state;
- previous contact orientation;
- optional per-tuft displacement later.

### Brush Contact State

Renderer-independent output describing the instantaneous brush/canvas footprint:

- width/radius multiplier;
- aspect ratio;
- contact angle;
- pressure/contact fraction;
- splay;
- optional local contact offset;
- later: sub-tuft contacts.

Renderers must consume the resolved geometry; they must not independently reinterpret pressure/tilt mechanics.

---

## Phase M1 — Analytic contact deformation

**Goal:** make the footprint itself respond mechanically to pressure, tilt and stylus orientation.

First implementation:

- pressure → configurable radial splay/footprint expansion;
- tilt → configurable footprint flattening/elongation;
- stylus orientation → configurable contact-angle steering;
- existing sensor dynamics still compose with the mechanical result;
- static/default brushes remain byte-compatible when mechanics are disabled.

This phase uses the existing `Dab.radius`, `Dab.tipRatio` and `Dab.angleDeg` fields. No renderer fork is required.

### Exit gate

- pressure visibly broadens a mechanics-enabled brush without merely changing opacity;
- tilt changes aspect ratio;
- rotating the stylus rotates the contact footprint when enabled;
- default-disabled mechanics reproduces existing dab output;
- incremental live generation and canonical `BrushStamps.dynamicDabs` agree.

---

## Phase M2 — Stateful bend, lag and recovery

**Goal:** stop treating each dab as an independent instantaneous footprint.

Add a small stroke-local mechanical state:

- current bend vector;
- target bend from movement direction and tilt;
- stiffness / response rate;
- damping;
- recovery toward rest orientation;
- optional directional hysteresis.

Expected behavior:

- a soft brush lags behind sharp direction changes;
- a stiff brush tracks the hand quickly;
- fast movement bends farther than a slow drag;
- stopping lets the footprint recover;
- reversing direction produces a transient snap/flip rather than an immediate angle teleport.

No individual bristles yet.

### Exit gate

- visible lag/recovery is deterministic;
- cost is O(new dabs), not O(stroke history);
- live/commit results match within the existing provisional-lift rules;
- disabling the mechanic restores Phase M1/static behavior.

---

## Phase M3 — Brush archetype morphology

**Goal:** make brush types mechanically distinct rather than different static masks.

Introduce semantic shapes such as:

- Round;
- Flat;
- Filbert;
- Rigger/Liner;
- Fan;
- Rake/Comb.

Each archetype defines rest geometry and how M1/M2 deformation affects it.

Examples:

- Flat: strong angle sensitivity, lateral splay, broad edge/knife-edge transition.
- Round: radial splay, less orientation sensitivity.
- Filbert: rounded flat with softer edge transition.
- Rigger: long directional lag and narrow footprint.
- Fan: wide angular spread with multiple contact lobes.
- Rake: stable parallel contact bands.

### Exit gate

The same pressure/tilt/motion sequence produces recognizably different contact evolution for at least Round, Flat and Filbert without relying on canvas texture or paint mixing.

---

## Phase M4 — Coarse tuft / bristle-bundle mechanics

**Goal:** generate structured brush marks from brush geometry rather than random scatter.

Represent the tip as a small number of sub-tufts/bundles, initially analytic or spring-based rather than full PBD.

Each bundle may carry:

- root offset in ferrule-local space;
- rest direction;
- stiffness;
- current bend/contact offset;
- cohesion to neighbors;
- local width/contact weight.

Mechanical outputs:

- pressure splay;
- directional bend;
- bundle separation;
- rake/comb striation;
- fan spreading;
- coherent split tips;
- snap-back/recovery.

Material load is **not required** for this phase. Splitting/cohesion must first work as a geometric brush model.

### Algorithm progression

1. analytic sub-tuft offsets;
2. damped spring bundle state;
3. constrained/PBD bundle solver only if necessary;
4. individual-bristle simulation only if bundle mechanics visibly fail.

### Exit gate

- structured parallel/branching marks emerge from stable tuft geometry;
- no pure-random-noise substitute for bristles;
- bundle count is capability-tiered and bounded;
- deterministic replay is preserved.

---

## Phase M5 — Touchdown, dwell, lift and direction-change mechanics

Graffux already has taper/blot behavior. Consolidate these into the contact model so they become coherent brush mechanics rather than isolated modifiers.

Focus on:

- first-contact compression;
- splay growth while dwelling;
- transition from stab to drag;
- contact recovery when movement begins;
- lift-off narrowing/recovery;
- fast flick vs slow lift;
- reversal snap;
- cornering behavior.

Existing `BrushBlot` and taper compatibility must be preserved or versioned explicitly.

---

## Phase M6 — Native/GPU and performance hardening

Because M1–M4 resolve geometry before rendering, most mechanics should remain renderer-independent.

Required gates:

- CPU/Vulkan consume identical resolved geometry;
- no renderer-specific pressure/tilt reinterpretation;
- incremental generator remains bounded with stroke length;
- no unbounded tuft simulation queue;
- capability tiers can reduce tuft count or solver iterations;
- Basic Brush/static path remains the latency baseline.

---

## Immediate implementation tranche

### Tranche M1-A — Contact-state contract

1. Add renderer-independent `BrushContactConfig` and `BrushContactState` in `core/engine`.
2. Add a pure deterministic `BrushContactModel.resolve(...)`.
3. Default configuration is disabled/identity.
4. Resolve:
   - pressure splay → width multiplier;
   - tilt flattening → aspect-ratio multiplier;
   - stylus orientation → optional footprint angle steering.
5. Integrate the result into both:
   - canonical `BrushStamps.dynamicDabs`;
   - `IncrementalDynamicDabGenerator`.
6. Make dynamic-path selection include enabled contact mechanics.
7. Add golden tests for pressure, tilt, orientation, disabled compatibility and live/commit parity.
8. Do **not** add material transfer, canvas texture, wetness, color or fluid behavior in this tranche.

### Tranche M1-B — Mechanical controls

Only after M1-A passes:

- expose a compact Brush Studio section:
  - Splay;
  - Tilt shape;
  - Orientation follow.

No broader media controls belong in this mechanical section.

---

## Priority statement

From this point forward, when choosing between a paint/material improvement and a brushstroke-mechanics improvement, **brushstroke mechanics wins unless the material work is required to preserve correctness of already-landed behavior**.
